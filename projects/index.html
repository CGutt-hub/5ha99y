EmotiView: Neural-Autonomic Synchrony and Embodied Integration

This repository accompanies ongoing research investigating the dynamic interplay between neural activity and autonomic nervous system responses during emotional experiences. Here you'll find the research article, presentations, analysis pipeline, and results—updated in real-time as the project progresses.

Principal Investigator: Cagatay Özcan Jagiello Gutt

Research Abstract

Emotional states are fundamentally embodied, emerging from the dynamic interplay between central neural processing and peripheral physiological adjustments orchestrated by the autonomic nervous system (ANS). While ANS outputs like heart rate variability (HRV) and electrodermal activity (EDA) reflect emotional arousal and valence, understanding the precise temporal coordination between brain activity and these peripheral signals is crucial for elucidating brain-body interactions. This study investigates neural-autonomic phase synchrony during the conscious processing of distinct emotional states (positive, negative, neutral) by quantifying the temporal alignment between cortical and physiological rhythms.

We employ a multimodal approach, simultaneously recording high-temporal-resolution electroencephalography (EEG), electrocardiography (ECG) for HRV analysis (specifically Root Mean Square of Successive Differences, RMSSD), EDA, and functional near-infrared spectroscopy (fNIRS) while participants view validated emotional video clips. Our primary analysis quantifies the Phase Locking Value (PLV) between frontal EEG oscillations (Alpha, Beta bands) and continuous signals derived from HRV (reflecting parasympathetic influence) and phasic EDA (reflecting sympathetic influence). EEG channel selection for PLV analysis is informed by task-related hemodynamic activity measured via fNIRS to focus on functionally relevant cortical areas.

We hypothesize that PLV, indicating brain-body temporal integration, will be significantly modulated by emotional content compared to neutral conditions. We further expect synchrony strength to correlate with subjective arousal ratings. By examining the phase synchrony between brain signals and ANS-mediated physiological outputs, this research provides novel insights into the dynamic, embodied mechanisms underlying emotional experience. Understanding this temporal binding is critical for models of psychophysiological function and may inform assessments of cognitive load or stress regulation capacity.

Core Research Aims & Hypotheses

This project seeks to understand how the brain and body coordinate during emotional processing, focusing on neural-autonomic phase synchrony. Key hypotheses include:

  1. Emotional Modulation of Synchrony: Neural-autonomic synchrony (Phase Locking Value - PLV) will be enhanced during the processing of positive and negative emotional stimuli compared to neutral stimuli, for both brain-heart (EEG-HRV) and brain-sudomotor (EEG-EDA) coupling.
  2. Synchrony and Subjective Arousal: The magnitude of neural-autonomic synchrony will positively correlate with subjective ratings of emotional arousal during emotional conditions.
  3. Baseline Vagal Tone and Task-Related Synchrony: Individual differences in baseline parasympathetic regulation (resting-state RMSSD) will be associated with the degree of EEG-HRV synchrony during negative emotional stimuli.
  4. Frontal Asymmetry and Branch-Specific Synchrony: The direction of prefrontal cortical asymmetry (Frontal Asymmetry Index - FAI) will be differentially associated with the strength of phase synchrony involving distinct autonomic branches (EEG-HRV vs. EEG-EDA).

For a comprehensive understanding of the theoretical background, detailed methodology, and specific work packages, please refer to the full proposal document.

Methodology Overview

A multimodal experimental design is employed, involving:

  • Stimuli: Standardized, emotionally evocative video clips (positive, negative, neutral) from the E-MOVIE database.
  • Participants: Healthy young adults, screened for relevant criteria.
  • Data Acquisition: Simultaneous recording of:
    • Electroencephalography (EEG): To measure prefrontal neural dynamics.
    • Functional Near-Infrared Spectroscopy (fNIRS): To localize hemodynamic activity in prefrontal and parietal regions, informing EEG channel selection.
    • Electrocardiography (ECG): For Heart Rate Variability (HRV) analysis.
    • Electrodermal Activity (EDA): To measure sympathetic nervous system activity.
  • Subjective Measures: Self-Assessment Manikin (SAM) for valence and arousal, Positive and Negative Affect Schedule (PANAS), and Behavioural Inhibition/Approach System (BIS/BAS) scales.

The analysis pipeline is built on the AnalysisToolbox—a modular Nextflow framework for scalable, reproducible data processing with automatic result synchronization. The EmotiView-specific pipeline in EV_analysis/ extends this framework to:

  • Load and parse multi-modal raw data (EEG, fNIRS, ECG, EDA, questionnaires).
  • Perform standardized preprocessing steps specific to each physiological modality.
  • Extract key features and metrics (e.g., EEG power, FAI, RMSSD, fNIRS ROI activation, PLV).
  • Generate participant-level results and aggregated summaries.

Ambient News Ticker — Forecast & Salience Monitor

An ambient signal-monitoring and probabilistic forecasting application built with Python and PyQt5. It ingests headlines and claims from RSS/Atom feeds, web/index discovery, and optional RF/SDR/teletext routes, partitions observations into dynamic topic clusters, updates event probabilities over time, and surfaces high-signal alerts on a scrolling marquee ticker.

Rather than ranking observations by engagement or conflating repetition with evidential support, the system maintains a Fermi-decomposed probabilistic forecast per cluster and decouples cross-channel salience from independent corroboration confidence, emitting excerpt-grounded alerts only when multi-signal Power Level or surge criteria are satisfied.

Key Capabilities

  • Multi-Stream Acquisition & Auto-Discovery: Polls configured RSS/Atom feeds, web/teletext/radio URLs, and RF/SDR callbacks or endpoints across route modes (auto, rf_and_web, web_only, rf_only), with automatic network/RF probing, background web/RSS crawling (scrape_web_for_news_sources), and domain/URL approval or blocklists persisted in JSON.
  • Duplicate & Echo Suppression: Detects redundant or echoed reports via lexical sequence similarity (>= 0.72) and token cosine similarity (>= 0.78), discounting echo evidential weight (0.15x) while preserving visibility in channel-spread metrics.
  • Fermi Decomposition & Log-Odds Bayesian Updating: Synthesizes initial forecast probabilities across weighted conditional Fermi drivers and optional reference-class base rates in log-odds space (ForecastQuestion.compute_fermi_prior), applying sequential log-odds updates with step_gain = 0.55 and archiving probability snapshots.
  • Dual-Signal Gating, Shadow Logging & Calibration: Separates broadcast Salience ($S$) from Corroboration Confidence ($C$), modulates impact via a continuous InterestProfile multiplier, logs evaluations to SQLite (newsticker_shadow.sqlite) with Shadow Mode support, and computes post-resolution Brier scores.
  • Interactive PyQt5 Monitor & Dynamic TTL Marquee: Provides real-time inspection of topic clusters, provenance states, evaluated items, and grounded excerpts alongside a continuous marquee strip (TickerMarqueeWidget) with queue-pressure and signal-strength-modulated time-to-live (TTL) expiration.

1. Architecture & Modeling Principles

The system transforms an asynchronous stream of textual observations into auditable, excerpt-grounded ticker alerts through five stages:

  1. Provenance-Preserving Ingestion: Each observation records item ID, channel identity, frequency/transmission band, source reliability weight, transcription confidence, timestamp, payload text, and optional metadata.
  2. Claim Parsing & Echo Attribution: default_claim_parser extracts certainty, directional signal, normalized tokens, and top topics, while _detect_echo checks prior cluster evidence to distinguish novel origins from echoes.
  3. Dynamic Topic Clustering: _match_or_create_cluster matches claims against existing clusters via token cosine similarity (>= 0.24) or creates a new cluster with inferred domain (maritime, infrastructure, geopolitics, general) and regime (baseline, elevated) tags and an attached ForecastQuestion.
  4. Fermi Prior & Log-Odds Sequential Updating: Active forecast questions combine conditional driver probabilities and optional base rates in log-odds space and update sequentially (step_gain = 0.55) as weighted directional evidence arrives.
  5. Dual-Signal Evaluation & Gated Emission: Salience, unexpectedness, time-decayed accumulation, and corroboration confidence are computed independently, modulated by InterestProfile relevance, and gated by cooldown windows, alert thresholds, and Shadow Mode.

2. Formal Notation & Observation Model

Consider a temporally ordered sequence of observations arriving at timestamps $t_1 \le t_2 \le \dots \le t_n$, where observation $i$ is defined as:

$$x_i = \big(c_i,, b_i,, w^{\text{src}}_i,, t_i,, \tau_i,, \gamma_i\big)$$

  • $c_i \in \mathcal{C}$: channel or source identifier, with $|\mathcal{C}| = N_c$ total monitored channels (8 in build_production_engine()).
  • $b_i$: transmission band or medium (e.g., shortwave, teletext, rss, vhf, navtex, web-sdr).
  • $w^{\text{src}}_i \in [0.05, 0.95]$: reliability weight assigned to channel $c_i$.
  • $t_i$: observation timestamp.
  • $\tau_i \in [0, 1]$: transcription or optical/speech recognition confidence ($\tau_i = 1.0$ for direct manual text).
  • $\gamma_i$: raw text string.

From $\gamma_i$, default_claim_parser produces:

  • Certainty category $\kappa_i \in {\text{confirmed}, \text{reported}, \text{speculative}}$ with multiplier $\mu_{\text{cert}}(\kappa_i) \in {1.00, 0.78, 0.45}$.
  • Directional signal $d_i \in [-1, 1]$, computed from positive escalation/disruption indicators (+0.45 each) minus negative de-escalation/restoration indicators (-0.45 each), clamped to $[-1.0, 1.0]$.
  • Verbatim/truncated excerpt $e_i$ (up to 180 characters), token Counter, and extracted topic keywords.

3. Echo Detection & Evidential Weighting

3.1 Echo Criterion

For an observation $i$ assigned to cluster $k$ with prior evidence set $\mathcal{E}k$, pairwise lexical sequence similarity SequenceMatcher ratio $r{\text{seq}}(\gamma_i, \gamma_j)$ (on the first 240 lowercase characters) and token cosine similarity $s_{\cos}(\mathbf{v}_i, \mathbf{v}_j)$ are evaluated against $j \in \mathcal{E}k$. Observation $i$ is classified as an echo ($\mathbb{I}{\text{echo}}(i) = 1$) if:

$$\max_{j \in \mathcal{E}k} r{\text{seq}}(\gamma_i, \gamma_j) \ge 0.72 \quad \lor \quad \max_{j \in \mathcal{E}k} s{\cos}(\mathbf{v}_i, \mathbf{v}_j) \ge 0.78$$

When $\mathbb{I}{\text{echo}}(i) = 1$, item $i$ inherits the origin identifier $o_i = o{j^*}$ of its closest match; otherwise $o_i = i$. The independence multiplier is:

$$\mu_{\text{indep}}(i) = \begin{cases} 0.15, & \text{if } \mathbb{I}_{\text{echo}}(i) = 1 \ 1.00, & \text{otherwise.} \end{cases}$$

3.2 Evidential Weight

The evidential weight $W_i \ge 0$ of observation $i$ is:

$$W_i = w^{\text{src}}i \cdot \tau_i \cdot \mu{\text{cert}}(\kappa_i) \cdot \mu_{\text{indep}}(i)$$

Discounting echoed text in $W_i$ prevents near-duplicate rebroadcasts from inflating independent corroboration while preserving their contribution to cross-channel salience.

4. Fermi Decomposition & Log-Odds Forecast Updating

4.1 Fermi Driver Aggregation & Base-Rate Blending

For a cluster $k$ with an attached ForecastQuestion (impact $I_k \in [0.10, 1.00]$) and $M$ conditional Fermi drivers ($m = 1, \dots, M$), each with probability $p_m \in [0.01, 0.99]$ and weight $\omega_m \ge 0$:

$$z^{\text{drv}}k = \sum{m=1}^{M} \tilde{\omega}_m \operatorname{logit}(p_m), \qquad \tilde{\omega}m = \frac{\omega_m}{\sum{r=1}^{M} \omega_r}$$

(If total driver weight is zero, compute_fermi_prior() averages driver probabilities directly; if there are no drivers, it defaults to 0.45.)

When a reference-class base rate $p^{\text{base}}k \in [0.01, 0.99]$ is set with weight $w{\text{base}} \in [0, 0.90]$, the Fermi prior blends base rate and driver log-odds:

$$p^{(0)}k = \operatorname{clip}!\Big(\sigma!\big(w{\text{base}} \operatorname{logit}(p^{\text{base}}k) + (1 - w{\text{base}}) z^{\text{drv}}_k\big),, 0.01,, 0.99\Big)$$

In NewsTickerGui_2.py, saving changes in FermiForecastDialog resets probability to the new Fermi prior only when the cluster has no stored evidence yet (reset_probability=not has_evidence), preserving prior evidence updates on active clusters.

4.2 Sequential Log-Odds Update

When an unresolved forecast is attached at timestamp $t_i$, the pre-update probability $p^{\text{prior}}_k \in [0.01, 0.99]$ is recorded and updated with step_gain $\alpha = 0.55$:

$$z^{\text{post}}_k = \operatorname{logit}(p^{\text{prior}}_k) + \alpha , d_i , W_i$$

$$p^{\text{post}}_k = \operatorname{clip}!\big(\sigma(z^{\text{post}}_k),, 0.01,, 0.99\big)$$

Each update appends a ForecastSnapshot to fc.history.

5. Diagnostic Signals & Composite Power

All quantities below are computed at observation timestamp $t = t_i$.

5.1 Salience ($S$)

Let $\mathcal{C}{6\text{h}}(k, t)$ and $\mathcal{C}{1\text{h}}(k, t)$ denote the sets of unique channels with evidence in cluster $k$ during $[t - 6\text{h}, t]$ and $[t - 1\text{h}, t]$:

$$S(k, t) = \operatorname{clip}!\left(0.55 \frac{|\mathcal{C}{6\text{h}}(k, t)|}{N_c} + 0.65 \frac{|\mathcal{C}{1\text{h}}(k, t)|}{N_c},; 0.0,; 1.0\right)$$

5.2 Unexpectedness ($U$)

Unexpectedness scales the single-step probability shift relative to 0.20:

$$U_i = \begin{cases} \operatorname{clip}!\left(\dfrac{|p^{\text{post}}_k - p^{\text{prior}}_k|}{0.20},; 0.0,; 1.0\right), & \text{if } p^{\text{prior}}_k \text{ and } p^{\text{post}}_k \text{ exist} \ 0.0, & \text{otherwise.} \end{cases}$$

5.3 Time-Decayed Accumulation ($A$)

Define outcome openness $\mathcal{O}_k(p) = 1.0$ if $p$ is None or $0.03 < p < 0.97$, and $0.25$ otherwise. With a $36\text{-hour}$ exponential decay constant and saturation denominator 1.4:

$$A(k, t) = \operatorname{clip}!\left(\mathcal{O}k(p) \left[1 - \exp!\left(-\frac{1}{1.4} \sum{j \in \mathcal{E}_k,, t_j \le t} W_j \exp!\left(-\frac{\max(0, t - t_j)}{36\text{h}}\right)\right)\right],; 0.0,; 1.0\right)$$

5.4 Corroboration Confidence ($C$) & Provenance Classification

Let $\mathcal{I}_k \subseteq \mathcal{E}_k$ denote non-echo origin items (not ev.is_echo) with $W_j \ge 0.20$, and let $\bar{q}_k$ be the mean of $\operatorname{clamp}(w^{\text{src}}_j, 0.05, 0.95) \cdot \operatorname{clamp}(\tau_j, 0.0, 1.0)$ over $j \in \mathcal{I}_k$ (or 0.10 if $\mathcal{I}_k$ is empty). Confidence is:

$$C(k, t) = \operatorname{clip}!\left(\big(1 - e^{-|\mathcal{I}_k|/2}\big)\big(0.40 + 0.60,\bar{q}_k\big),; 0.0,; 1.0\right)$$

Provenance classification (_compute_confidence) assigns one of five labels based on origin count, quality, directional disagreement ($d_j > 0.2$ and $d_m < -0.2$ among origins with $|\mathcal{I}_k| \ge 2$), confidence, and surge threshold $\theta_S$:

  • DISPUTED: Opposing directional signals across $|\mathcal{I}_k| \ge 2$ origin items.
  • CORROBORATED: $|\mathcal{I}_k| \ge 2$ origin items with $C \ge 0.45$ and no dispute.
  • OBSERVED: $|\mathcal{I}_k| = 1$ origin item with $\bar{q}_k \ge 0.60$.
  • CIRCULATING / SURGING: Salience satisfies $S \ge \theta_S$ without corroborated or observed status.
  • UNVERIFIED / CIRCULATING: Claims below surge and corroboration criteria.

5.5 Interest Modulation & Power Level ($\Psi$)

For interest score $\eta_i \in [0, 1]$ from InterestProfile.score_text:

$$\mu_{\text{int}}(\eta_i) = \begin{cases} 1.0 - (1.0 - m_{\text{out}}),\operatorname{clip}!\big(2(0.50 - \eta_i),, 0.0,, 1.0\big), & \text{if } \eta_i < 0.50 \ 1.0 + (m_{\text{in}} - 1.0),\operatorname{clip}!\big(2(\eta_i - 0.50),, 0.0,, 1.0\big), & \text{if } \eta_i \ge 0.50. \end{cases}$$

With effective impact $I^{\text{eff}}{k,i} = I_k \cdot \mu{\text{int}}(\eta_i)$ (default impact 0.45 if no forecast is attached), composite Power Level is:

$$\Psi_i = I^{\text{eff}}_{k,i} \Big(0.45,S(k, t_i) + 0.55,U_i,C(k, t_i) + 0.45,A(k, t_i),C(k, t_i)\Big)$$

6. Alert Gating, Dynamic TTL, Shadow Logging & Calibration

6.1 Trigger Set, Cooldown & Emission Rule

Three trigger conditions are checked at each ingestion:

  • rapid_broadcast_surge: $S \ge \theta_S$ (0.62 default)
  • unexpected_development: $U_i,C(k, t_i) \ge 0.18$
  • sustained_accumulation: $A(k, t_i),C(k, t_i) \ge 0.28$

A cooldown window of cooldown_sec = 120.0s since cluster.last_alert_at suppresses repeated alerts unless rapid_broadcast_surge or unexpected_development is triggered. Outside cooldown (or when overridden), an alert is emitted when $\Psi_i \ge \theta_{\Psi}$ (0.36 default), rapid_broadcast_surge is triggered, or unexpected_development is triggered—provided shadow_mode is False. Emitted alerts format as:

[{provenance_tag} · Ψ={power_level:.2f} P={posterior_prob:.0%}] {excerpt}

6.2 Dynamic Marquee Time-to-Live (TTL)

In TickerMarqueeWidget, queued alerts expire dynamically according to queue length $Q$, alert power $\Psi_i$, and surge flag $\mathbb{I}{\text{surge}}$, clamped to $[\text{TTL}{\min}, \text{TTL}{\max}] = [180\text{s}, 10800\text{s}]$ around $\text{TTL}{\text{base}} = 1800\text{s}$:

$$\text{TTL}i = \operatorname{clip}!\left(\text{TTL}{\text{base}} \cdot \frac{1}{1 + 0.15\max(0, Q - 1)} \cdot \Big(0.75 + \min(0.65,, 0.70,\Psi_i) + 0.20,\mathbb{I}{\text{surge}}\Big),; \text{TTL}{\min},; \text{TTL}_{\max}\right)$$

Users can click the marquee or use pause scroll, prev, and next to inspect items interactively.

6.3 Shadow Mode & Brier Score Calibration

When shadow_mode is enabled, evaluations are written to the evaluations table in newsticker_shadow.sqlite without emitting live ticker alerts. Resolving a cluster's forecast question (YES / NO in FermiForecastDialog or engine.resolve_question) computes its Brier score and updates the window's mean brier readout:

$$\text{BS} = (p - y)^2 \in [0, 1], \qquad y \in {0, 1}$$

7. Extensions & Methodological Refinements

  • Structured Claim Extraction: Replace keyword/regex heuristics in default_claim_parser with typed schema extraction (e.g., BAML or structured LLM outputs) or specialized domain lexicons.
  • Dense Semantic Representation: Augment token cosine similarity and SequenceMatcher ratios in _match_or_create_cluster and _detect_echo with dense embeddings for stronger paraphrase and cross-lingual matching.
  • Empirical Calibration: Tune source weights, Fermi priors/base rates, decay constants, and alert thresholds $(\theta_{\Psi}, \theta_S)$ using logged SQLite evaluations and resolved Brier scores.

AnalysisToolbox

A modular framework for automated data processing and statistical analysis pipelines. Built on Nextflow for scalable, reproducible workflows with automatic result synchronization.

Overview

The AnalysisToolbox provides infrastructure for building data processing pipelines that:

  • Process multiple datasets in parallel with automatic participant discovery
  • Handle diverse data types through a generic reader/processor/analyzer architecture
  • Track progress via per-participant logging visible live in the web UI
  • Recover gracefully from failures without losing completed work

The framework is domain-agnostic — modules follow simple input/output conventions (Parquet/FIF files) and can implement any processing logic.

IOInterface

Generic Nextflow process that runs any script (reader/processor/analyzer) with automatic logging. Every module in modules/ is called through IOInterface.

Modules

The modules/ folder is a curated but non-exhaustive starting collection of commonly useful scripts. The first time gitatbx is run it mirrors the full collection to ~/Documents/GitAtbxModules (Windows) or ~/GitAtbxModules (Linux/macOS) automatically. You can move that folder anywhere with gitatbx move. The local copy is yours to extend: add domain-specific scripts, modify existing ones, or organise them into subfolders. Any script there can be called via IOInterface identically to the built-in modules, as long as it follows the same convention: positional CLI arguments in, Parquet or FIF outputs, non-zero exit on failure.

Survey Workbench

A desktop workbench for study coordinators and researchers. Prepare standardized participant folders with fillable PDF questionnaires, prefill initial values, and extract completed survey answers directly into Apache Parquet, Excel workbooks, CSV, TSV, or JSON masterfiles.

1. Overview & Key Features

  • Multi-Format Masterfile Exports:
    • Microsoft Excel (.xlsx, .xls): Dedicated tabs per questionnaire type, placing each participant at their preassigned row (x + 1) and keeping schemas clean and isolated.
    • Apache Parquet (.parquet): High-speed columnar storage optimized for data science pipelines (Python, R, Polars, DuckDB, Julia).
    • Delimited Text (.csv, .tsv, .tab): Standard comma- or tab-separated tables with zero third-party dependencies.
    • Structured JSON (.json): Human-readable, structured data arrays.
  • Canonical Grammar Consolidation: Automatically groups checkbox arrays (like Check1_1, Check1_2) into a single column (Check1) containing only the ticked option identifier(s), ignoring unticked states (Off, False, 0, No, Aus, Nein, etc.) and respecting PDF /NeedAppearances.
  • Ignore / NOT Operator (_ prefix or _n suffix): Any field prefixed with a leading _ (e.g., _Text13) or suffixed with _n (e.g., Text13_n) is omitted from masterfile exports.
  • Condition Ordering (con Field): Supports counterbalanced / mixed-order repeated surveys via a dedicated con (or _con / con_n) PDF field and File -> Save/Edit Condition Ordering (Numerical as standard, or custom mappings & meanings saved to survey_workbench.config).
  • Filename-Driven Sheet Routing: Automatically derives the masterfile sheet name directly from the PDF filename (e.g., WaS3_001_nasa_1.pdf -> nasa, WaS3_002_you_are_an_idiot_34.pdf -> you_are_an_idiot) and appends numbered copies (nasa_1, nasa_2, nasa_3, ...) horizontally in the same participant row.
  • Preassigned Excel Row Placement (x + 1): In Excel sheets, participant x (e.g., 1, P001, WaS3_001) is always placed in row x + 1 (row 2 for participant 1, row 3 for participant 2, etc.) rather than simply appending to the bottom.
  • Consolidated Batch Processing & Interactive Selection: Enter single IDs, paste multiple IDs, or import participant lists from text or CSV files. During extraction, an interactive checklist presents all participants in the batch (showing New vs Already in Masterfile (will overwrite)) so you can untick anyone you do not want to export.
  • Unified Batch Preview Table: Both folder generation and masterfile extraction open a single, consolidated table displaying all participants at once. Inspect and edit friendly header names and questionnaire answers before committing any changes.
  • Safe Staging: Prefill values and survey folders are validated in memory before any directory is modified on disk. If you cancel, nothing is touched.
  • Collapsible Workspace & Dynamic Resizing: Curator settings stay tucked inside a collapsible drawer, leaving a clean, compact window that automatically resizes to fit active study configurations.
  • Cross-Project Field Mapping Import: Instantly copy friendly column header names from any previously saved study profile via the File -> Import Field Mapping submenu.
  • Natural Alphanumeric Sorting: Columns and previews are sorted naturally (Text1, Text2, ..., Text10) instead of alphabetical order (Text1, Text10, Text2).
  • Project Snapshotting: Save and reload complete project setups (paths, templates, copy counts, custom column names, and condition orderings) to and from survey_workbench.config.
  • Pre-Compiled & Cross-Platform: Standalone Windows executable (.exe) ready to download without setup; native Linux binary easily built with Nuitka.
  • Built-in Interactive Help & Diagnostics: Hover tooltips, "What's This?" click mode, an in-app viewer for this manual, and HELP -> Inspect PDF Form Fields... to inspect raw PDF field states.

2. Canonical Form Field Grammar

PDF form fields must adhere to the following specification:

(_){Check, Text}<i>(_n) and optionally (_)con(_n)

Breakdown of Grammar Elements:

ElementDescriptionMasterfile & Workflow Behavior
_ or _nNOT Operator (leading _ prefix or trailing _n suffix)If a field (or any segment in its hierarchy) starts with _ or ends with _n (e.g., _Text13, Text13_n, _Check5_1, Check5_n), it does NOT get exported into the masterfile. Ideal for administrative cover-page notes, visual participant ID labels, print-only metadata, or routing-only _con / con_n fields.
{Check, Text}Entry TypeDeclares the input type. Text fields capture verbatim strings. Check fields represent boolean, binary, or nominal selection controls.
<i>Field / Question IndexIndex number of the form question or condition. If option buttons belong to the same question, i stays constant while n changes.
_n (numeric/option)Option Identifier (on Check<i>_1, Check<i>_2, ...)Specifies the choice identifier. In the masterfile, the cell shows n for column Check<i> if that specific box is checked. (Note: literal _n at the end is treated as the NOT/ignore suffix.)
(_)con(_n)Condition Field (optional, case-insensitive)Declares the experimental condition of a repeated survey (text field, dropdown, radio group, or con_<opt> checkboxes) so mixed-order PDFs align cleanly in the masterfile row. Use _con (or con_n) to route without exporting a con column, or con to both route and export <prefix>con.

Concrete Examples:

  1. Nominal / Likert Scales (Check1_1 to Check1_5):
    • Options are named Check1_1, Check1_2, Check1_3, Check1_4, Check1_5.
    • If the participant selects the 3rd box (Check1_3), the masterfile stores 3 in the column Check1.
    • Unticked boxes (Off, False, No, 0, Aus, Nein, etc.) are ignored; no individual Check1_1, Check1_2, etc. columns clutter your masterfile.
  2. Binary Conditions (Check2_0 and Check2_1):
    • Canonically, 0 represents False/No and 1 represents True/Yes.
    • If the participant checks Check2_0, the masterfile records 0 in column Check2.
    • If the participant checks Check2_1, the masterfile records 1 in column Check2.
  3. Standalone Checkbox (Check3):
    • A single boolean checkbox without an option suffix.
    • If checked, the cell records 1; if unchecked, it records 0.
  4. Ignored Cover Fields (_Text13, Text13_n, _Check5_1, Check5_n):
    • Marked with a leading _ or trailing _n.
    • Can still be prefilled with the participant ID during folder generation so that it appears on the PDF form, but is completely omitted during extraction into the masterfile.
  5. Counterbalanced Condition Routing (con / _con / con_sf):
    • Suppose Participant 1 receives WaS3_001_nasa_1.pdf (con = 2 or con = sf) and WaS3_001_nasa_2.pdf (con = 1 or con = bl).
    • With numerical con (or bl = Order 1, sf = Order 2 configured in File -> Save/Edit Condition Ordering), nasa_2.pdf is routed into nasa_1_* (first block) and nasa_1.pdf is routed into nasa_2_* (second block), keeping every participant aligned by condition in the masterfile.
    • If marked as _con (or con_n), the field is used strictly for ordering and omitted from the exported columns.

Zero-Redundancy in Pop-Up Tables:

All pop-up tables (Save/Edit Field Mapping, Batch Generation Prefill, and Extraction Review) automatically consolidate all Check<i>_1..k fields into a single Check<i> entry. Defining names or mappings for every individual option is completely eliminated.

5. Masterfile Formats, Sheet Naming & Row Placement

  • Sheet / File Base Naming: Sheet names are derived directly from the PDF filename after stripping the participant ID prefix and any trailing copy indices (e.g., WaS3_001_nasa_1.pdf, WaS3_001_nasa_2.pdf -> sheet nasa; WaS3_002_you_are_an_idiot_34.pdf -> sheet you_are_an_idiot).

  • Excel (.xlsx, .xls):
    • Each questionnaire base name is matched case-insensitively to an existing worksheet (or creates a new one if absent).
    • Participant x (determined by the trailing/single number in the ID, e.g., 1, P001, WaS3_001 -> 1) is written directly into their preassigned row x + 1 (leaving skipped participant rows empty instead of shifting rows up). Non-numeric IDs are appended after the last occupied row.
  • Parquet (.parquet): Automatically creates partitioned parquet tables named <masterfile>_<survey_name>.parquet.
  • CSV / TSV (.csv, .tsv): Automatically writes partitioned files named <masterfile>_<survey_name>.csv / .tsv.
  • JSON (.json): Automatically writes arrays named <masterfile>_<survey_name>.json.

labourAIVolt: AI & Human Labour Displacement Analysis for Volt

This repository hosts a Nextflow + Python analysis pipeline that automatically fetches current labour-market data from the World Bank public API and quantifies AI-driven labour displacement across the six Volt EU countries with the most active chapters — Germany, France, the Netherlands, Belgium, Italy, and Spain.

The aim is to give Volt Europa and its national chapters an evidence base for labour-market and technology policy: which sectors are shedding jobs fastest as AI and automation accelerate, which countries are most exposed, and how does digital readiness moderate that exposure?

The pipeline is architecturally modelled after the EmotiView project and extends the AnalysisToolbox modular Nextflow framework for scalable, reproducible analysis with automatic result synchronisation.

PlatformRoleContents
GitHubTechnical implementationPipeline, scripts, results
World Bank APIData sourceLive labour-market indicators

Research Background

The labour-market impact of AI and automation is one of the defining policy challenges of the 2020s. Early projections (Frey & Osborne, 2013) estimated that up to 47 % of US jobs faced high computerisation risk; subsequent analyses have moderated that figure while broadening it to task-level disruption rather than wholesale job destruction. What is clear is that the pace and sector distribution of displacement vary substantially across countries depending on industrial structure, education levels, and digital infrastructure.

For a pan-European political movement like Volt, the relevant questions are:

  1. Which EU sectors show the clearest employment decline correlated with automation?
  2. Are Volt's home countries converging toward or diverging from each other on displacement pressure?
  3. Does a country's digital readiness (internet penetration, high-tech exports) buffer it against displacement?
  4. Where should Volt's labour policy — reskilling funds, working-time reform, Universal Basic Income pilots — be concentrated first?

This pipeline operationalises those questions with reproducible, automatically updated data.

Core Research Questions & Hypotheses

  1. Sector displacement ordering: Industry and agriculture will show larger negative employment-share trends than services, consistent with higher Frey & Osborne automation risk for routine physical/cognitive tasks.

  2. Cross-country heterogeneity: Countries with larger manufacturing sectors (Germany, Italy) will exhibit higher AI Displacement Pressure Index (ADPI) than service-dominant economies (Netherlands, Belgium).

  3. Digitalization buffer: Countries with higher Digitalization Readiness Scores (internet penetration + high-tech export share) will show lower net Vulnerability Scores, suggesting that digital transformation simultaneously creates displacement and provides adaptive capacity.

  4. Temporal acceleration: Employment-share trends will steepen post-2018 as AI adoption accelerates across all three sectors, visible as a structural break in the time-series.

Analysis Pipeline

The pipeline is built on the AnalysisToolbox — a modular Nextflow framework for scalable, reproducible data processing with automatic result synchronisation. The LAV-specific pipeline in LAV_analysis/ extends this framework to:

  • Discover country datasets and create per-country output directories (L1).
  • Fetch and parse live labour-market time-series from the World Bank API.
  • Perform standardised normalisation and cleaning.
  • Extract displacement signals and automation-risk-weighted scores per sector.
  • Fit time-series trend models to all available indicators.
  • Aggregate across countries into cross-country rankings and Volt policy metrics (L2).

Configuration is managed via LAV_analysis/LAV_parameters.config. See the AnalysisToolbox documentation for framework details.

displacement_score  =  displacement_signal  ×  automation_risk

automation_riskSector-level probability of computerisation from Frey & Osborne (2013): agriculture 0.82, industry 0.79, services 0.63.
displacement_scoreComposite: high score = fast employment decline and high intrinsic automation susceptibility.

Running the Analysis

Option A — GitHub Actions (recommended — no local setup needed)

The workflow in .github/workflows/lav_analysis.yml runs automatically:

TriggerWhen
ScheduledEvery Monday at 06:00 UTC (pulls the latest World Bank data)
On pushAny change to LAV_data/** or Python/** on main
ManualActions tab → LAV Labour-AI-Volt Analysis → Run workflow

Results are:

  1. Uploaded as a downloadable artifact (lav-results-<run-number>) for 90 days.
  2. Committed back to LAV_results/ in the repository so outputs are versioned alongside the code.

No API keys, secrets, or local software are required.

Option B — Standalone Python (local, no Nextflow)

Use this for quick local runs or debugging individual scripts.

# 1. Clone the repository
git clone https://github.com/CGutt-hub/labourAIVolt.git
cd labourAIVolt

# 2. Install Python dependencies
pip install -r Python/requirements.txt

# 3. Run the full pipeline
python Python/lav_run.py

# Optional: override data/output directories
python Python/lav_run.py --data-dir LAV_data --output-dir LAV_results

Results are written to LAV_results/LAV_l1/<id>/ (per country) and LAV_results/LAV_l2/ (group synthesis).

Option C — Full Nextflow Pipeline (local, requires AnalysisToolbox)

Use this for full pipeline tracing, parallel execution, and integration with the AnalysisToolbox interactive HTML archive.

Prerequisites: Java ≥ 11, Nextflow

# 1. Clone both repos as siblings
git clone https://github.com/CGutt-hub/labourAIVolt.git
git clone https://github.com/CGutt-hub/AnalysisToolbox.git

# Your directory should now look like:
#   parent/
#   ├── AnalysisToolbox/
#   └── labourAIVolt/

# 2. Install Python dependencies
cd labourAIVolt
pip install -r Python/requirements.txt

# 3. Adjust python_exe in LAV_parameters.config if needed
#    (default: 'python3')

# 4. Launch the pipeline from the LAV_analysis/ directory
cd LAV_analysis
nextflow run LAV_pipeline.nf -c LAV_parameters.config

The Nextflow pipeline adds on top of the standalone runner:

  • Parallel per-country execution
  • Full Nextflow trace (LAV_results/.bin/pipeline_trace.txt)
  • Interactive HTML result archive (via AnalysisToolbox interactive_plotter)
  • Automatic git commit + push of results after each country completes

Output Files Reference

Per-country (L1) — LAV_results/LAV_l1/LAV_XXX/

FileDescription
LAV_XXX_api_raw.parquetRaw long-format data as returned by the World Bank API. Columns: participant_id, country, iso3, source, indicator, indicator_code, year, value.
LAV_XXX_normalized.parquetWide-format time-series. One row per year, one column per indicator. Ready for analysis scripts.
LAV_XXX_displacement.parquetPer-sector displacement scores. Key columns: sector, employment_mean_pct, trend_slope_pp_per_yr, trend_significant, automation_risk_frey_osborne, displacement_score.
LAV_XXX_trends.parquetOLS trend results for every indicator. Key columns: indicator, trend_slope, trend_p_value, trend_r_squared, trend_significant, total_change_pct.
LAV_XXX.log.parquetLive pipeline execution log (Nextflow mode only).

Group-level (L2) — LAV_results/LAV_l2/

FileDescription
LAV_volt_report.parquetFull combined table (displacement + policy metrics for all countries).
LAV_displacement_summary.parquetCross-country displacement ranking per sector, with EU-wide mean, std, and per-country rank.
LAV_trends_summary.parquetEU-wide mean slope and significance counts for key indicators across all countries.

Adding a New Country

  1. Create a new directory: LAV_data/LAV_007/
  2. Add a config file LAV_data/LAV_007/LAV_007_config.json:
{
  "participant_id": "LAV_007",
  "country": "Portugal",
  "iso3": "PRT",
  "iso2": "PT",
  "year_start": 2010,
  "year_end": 2025,
  "volt_chapter": "Volt Portugal",
  "population_millions": 10.3,
  "eu_member": true,
  "notes": "Optional notes about the country context"
}
  1. Push the file — the GitHub Action will pick it up automatically on the next run.
